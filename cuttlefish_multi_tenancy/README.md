# Example configuration for using Cuttlefish Multi-tenancy with SDV

[Cuttlefish multi-tenancy](https://source.android.com/docs/devices/cuttlefish/multi-tenancy)
allows for your host machine to launch multiple virtual guest devices with a
single launch invocation. This page describes how to use multi-tenancy with SDV.

## Prerequisites

Setup the environment and build the SDV Core VM.

```shell
export OUT_DIR=out_sdv_core
source build/envsetup.sh
lunch sdv_core_cf-trunk_staging-userdebug
m
```

## Complete the canonical configuration

Multi-tenancy requires a canonical configuration that describes the
configuration for host and the guest machines. Note that the Cuttlefish
configuration selected in the `android-info.txt`, for instance,
`sdv_core_cf/config/config_sdv.json`, is still taking affect, the canonical
configuration works on top of that.

Complete the canonical configuration in the `two-core-vms-example.json` file and
replace the `<REPLACE_THIS_BY_REPO_ROOT>` by the absolute path to your Android
repository.

## Start the VMs

Start the two SDV Core VMs defined in `two-core-vms-example.json` by running the
following command from the repo root:

```shell
cvd create --config_file=device/google/sdv/cuttlefish_multi_tenancy/two-core-vms-example.json
```

Once the `cvd start` has returned, you can verify that the VMs have appeared on
`adb` by executing `adb devices`:

```shell
List of devices attached
0.0.0.0:6520    device
0.0.0.0:6521    device
```

You can also query information about all the running instances managed by `cvd`
by executing `cvd fleet`:

```json
{
    "groups" :
    [
        {
            "group_name" : "cvd_1",
            "instances" :
            [
                {
                    "adb_serial" : "0.0.0.0:6521",
                    "assembly_dir" : "/tmp/cvd/760907/1711629524863732/home/cuttlefish/assembly",
                    "displays" :
                    [
                        "720 x 1280 ( 320 )"
                    ],
                    "instance_dir" : "/tmp/cvd/760907/1711629524863732/home/cuttlefish/instances/cvd-2",
                    "instance_name" : "2",
                    "status" : "Running",
                    "web_access" : "",
                    "webrtc_device_id" : "cvd-2",
                    "webrtc_port" : "443"
                },
                {
                    "adb_serial" : "0.0.0.0:6520",
                    "assembly_dir" : "/tmp/cvd/760907/1711629524863732/home/cuttlefish/assembly",
                    "displays" :
                    [
                        "720 x 1280 ( 320 )"
                    ],
                    "instance_dir" : "/tmp/cvd/760907/1711629524863732/home/cuttlefish/instances/cvd-1",
                    "instance_name" : "1",
                    "status" : "Running",
                    "web_access" : "",
                    "webrtc_device_id" : "cvd-1",
                    "webrtc_port" : "443"
                }
            ],
            "start_time" : "2024-03-28 12:38:45"
        }
    ]

```

where

*   `adb_serial`: the `adb` serial that can be used the specify the device when
    there are multiple using the `-s` parameter: `adb -s <adb_serial>`
*   `displays`: the displays that the instance had by default configuration or
    as specified by the canonical configuration in a `width x height ( dpi )`
    format
*   `instance_name`: the autogenerated instance name
*   `instance_dir`: the instance directory where, for instance, the instance's
    images, logs and the full cuttlefish configuration are located
*   `webrtc_port`: the port where you can view and interact with the instance's
    displays (if the instance is not headless, like SDV Core) in a browser on
    the `localhost`.

## Use the started VMs

You can use the started VMs, for instance, for running samples, such as
`system/software_defined_vehicle/core_services/samples/sdv_gateway/grpc_cpp`.
From the sample descriptions, skip the initial steps that build SDV and start
the VMs, because they are already running.

## Stop the VMs

You can use `cvd stop` for selecting individual VMs to shut down, or `cvd reset`
to shut down all VMs.

## More information

For more information, please refer to the
[Cuttlefish multi-tenancy](https://source.android.com/docs/devices/cuttlefish/multi-tenancy)
documentation.
